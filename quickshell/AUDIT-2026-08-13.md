# Yemi-Shell Audit Report — 2026-08-13

## 1. Wallpaper Persistence Bug — Root Cause

**BUG CONFIRMED.** The file `~/.local/state/quickshell-wallpaper` is stale and never updated by the live wallpaper pipeline.

State of record files:
| File | Current content | Last written by |
|------|----------------|-----------------|
| `~/.local/state/quickshell-wallpaper` | `wallhaven-po9eop.webp` | legacy `wallcolors.py` pipeline (stale) |
| `~/.local/state/yemi-shell/current-wallpaper` | `wallhaven-lyj56q.webp` | `sync-colors.sh` → `after-wall.sh` (live, correct) |

`wallpaper.sh` line 65-71 (`init` command) reads **only** `~/.local/state/quickshell-wallpaper`. On login, it finds the stale `wallhaven-po9eop.webp` and loads it, ignoring whatever the user set last session.

The live pipeline writes `~/.local/state/yemi-shell/current-wallpaper` (correct) but `wallpaper.sh init` never reads that file. The two state files are **divergent** and not synchronized.

**Fix direction:** `wallpaper.sh` line 89 (`printf '%s\n' "$pic" > "$STATE"`) already writes the state file. The issue is that `wallpaper.sh init` reads from a path that was correct in the old pywal era but is now never updated by the dominance engine pipeline. Either have `after-wall.sh` also write to `$STATE`, or change `wallpaper.sh init` to read from `yemi-shell/current-wallpaper` first.

## 8. Wallpaper Pipeline — Full Data Flow

```
1. User picks wallpaper via skwd-wall
2. skwd-wall runs externalWallpaperCommand:
   wallpaper.sh set %path% → sync-colors.sh %path%
3. sync-colors.sh writes yemi-shell/current-wallpaper = %path%
4. sync-colors.sh calls after-wall.sh %path%
5. after-wall.sh runs dominance-engine.py → colors.json v2
6. after-wall.sh writes:
   - ~/.cache/yemi-shell/colors.json  ← Dyn.qml reads THIS
   - ~/.cache/yemi-shell/terminal.json
   - ~/.cache/yemi-shell/hypr-colors.lua
7. wallpaper.sh set ALSO writes:
   - ~/.local/state/quickshell-wallpaper = %path%  ← this works correctly
   
BUT ON LOGIN:
1. autostart.lua runs wallpaper.sh init
2. wallpaper.sh init reads ~/.local/state/quickshell-wallpaper
3. Gets stale value (wallhaven-po9eop.webp) — NOT the last-set wallpaper
```

**The disconnect:** `after-wall.sh` reads `quickshell-wallpaper` for wallpaper resolution (line 32) but never writes to it. `wallpaper.sh set` does write it (line 89), but the bug is that `wallpaper.sh init` has no fallback to `yemi-shell/current-wallpaper` when the state file is stale.

The simplest fix: add `yemi-shell/current-wallpaper` as a fallback read in `wallpaper.sh init` (line 67), checking it before falling back to `pop_bag`.

### 9.1 Config Engine Trimmability

**CONFIG_ENGINE_TRIMABLE: yes**

`Config.qml` reads arbitrary JSON — sections come from the file, not hardcoded. Evidence:
- `setNestedValue(nestedKey, value)` — line 105 (generic key-path setter)
- `setNestedValues(updates)` — line 115 (batch setter)
- `_writeMirrorToDisk()` — line 246 (generic write-back)

`Config.options` is a dynamic `var` populated from whatever JSON is loaded. The engine will accept a trimmed `config.json` with only the sections waffle panels actually use.
